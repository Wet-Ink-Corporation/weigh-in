# May Weigh-In publish ledger items from IQBG client repos to a claude.ai Artifact board?

## Context and problem statement

Board items quote client code, requirements and your deliberations. The board keeps them on claude.ai, visible to your organisation, long after the session that raised them.

Door: one-way. Published excerpts can be deleted but not un-seen; a breach of client terms cannot be undone.

Timing: Decide now. The fact that would flip this (each client's terms on Anthropic as a subprocessor) is knowable per engagement today; waiting will not reveal it.

Resolve by: before slice 2 (the board) ships.

Evidence:

- [docs › artifacts] Artifacts need a claude.ai login and the Anthropic API (not Bedrock, Vertex or Foundry), and are unavailable in CMEK, HIPAA or ZDR organisations.
- [runtime › db] A board with a db store is organisation-internal and cannot be shared publicly. Any viewer can write the store, so answers read back are treated as untrusted.
- [session fact] Claude Code already sends the code in context to Anthropic during a session. The board adds persistence and an org-visible surface, not new processing.
- [settled · Q2] Records land in the same .kb layout everywhere, so the ledger stays in the repo whatever the board mode.

## Considered options

### A. Per-repo board mode; client repos default to local (chosen)

board: artifact | local | off in .kb/_ledger/config.json. Wet Ink and Redkiln repos use the Artifact board; client repos use the local page and in-chat cards until you switch one.

- Holds if: you can say at init whether a repo belongs to a client
- If wrong: one extra setting per repo; a client repo you would have allowed runs without the board until switched

### B. Artifact board in every repo

One surface everywhere, including client repos, reachable from Cowork, the desktop app and your phone.

- Holds if: every client's terms already allow Anthropic to process and store excerpts of their code
- If wrong: client excerpts persisted on claude.ai against their terms, beyond recall from anyone who viewed them

### C. No hosted board anywhere

Local review page and in-chat cards only, in every repo including your own.

- Holds if: you never need the board from Cowork, away from your machine, or on your phone
- If wrong: you lose the only surface that spans Claude Code and Cowork, for your own repos too

| Criterion | A | B | C |
|---|---|---|---|
| Client data stays off claude.ai | Yes, by default | No | Yes |
| Board from Cowork and phone | Your repos | Every repo | None |
| Setup per repo | One setting | None | None |
| Undo if wrong | Switch the setting | Not for what was published | Switch later |

## Decision outcome

Chosen: **A. Per-repo board mode; client repos default to local**, decided 2026-09-26T17:55:55Z.

The card's recommendation was A (shown options first with nothing pre-selected, because the door is one-way).
Trade-off: You are trading one uniform surface for a per-repo setting.
What would flip it: IQBG's standard client terms name Anthropic as an approved subprocessor for code excerpts. Then B for those clients.
Why it might be wrong: If every IQBG engagement already runs Claude Code under terms that cover Anthropic, the board's extra exposure is persistence and org visibility only, and the per-repo friction buys little.
Stability: 4 of 4 (Opus pick plus 3 Sonnet samples, each with the option order permuted and the recommendation removed). All samples judged options written by the same author, so this checks order and framing bias, not authorship bias.
