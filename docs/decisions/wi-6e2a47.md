# Where should Weigh-In keep its live ledger so that moving into redkiln-rs later adds no source-control friction?

## Context and problem statement

redkiln-rs keeps git as the authority for decisions and a derived store outside the working tree. A Weigh-In ledger committed as files would be a second shape that redkiln-rs has to import or ignore.

Door: two-way. Ledger files already pushed to your repos stay in history; everything else can move.

Timing: Decide now. Every session run before this is settled writes ledger files in whichever shape slice 1 ships.

Resolve by: before slice 1 starts.

This reopened the default wi-81b7aa. Ryan's note:

> redkiln-rs works slightly differently in terms of it's approach to git. weigh-in needs to stand on it's own until redkiln-rs is ready to integrate it - but we should anticipate that merge and ensure that we do not create friction from a source control perspective

Evidence:

- [crates/rk-store/src/conn.rs:72] redkiln-rs keeps one store per repository at <git-common-dir>/redkiln/store.sqlite3, shared by every worktree and never committed.
- [ADR-0018] Rows are keyed by SHA or tree hash, never branch or path; rebase and amend emit rewrite events; only the run-owned worktree writes.
- [ADR-0105 cl. 3-4] An answer is recorded as a trailer commit on the run's branch, with the tree hash taken from a temporary index (untracked files excluded).
- [operator-surface-proposal.md §12.3] git stays the tier-1 authority; the store is derived and rebuildable. F19 rebuilt 174 of 174 records from git.
- [ADR-0129] In Phase 1 only a CLI answer reconciles; a web view is not an answer channel. Board answers must therefore be applied by the CLI, as Weigh-In already does.
- [settled · wi-a93f02] You chose C: commit event files in your repos, keep them local in client repos. This card would supersede the committing half.

## Considered options

### A. Mirror redkiln-rs: git for decisions, a common-dir store for open items (chosen)

Open items live in <git-common-dir>/weighin/, shared by every worktree and never committed. Decisions reach git as .kb/_intake atoms plus a Weigh-In trailer on the enacting commit. Your repos mirror open items to the board for other machines.

- Holds if: you never need undecided items from a fresh clone of a client repo
- If wrong: open items in client repos stay on one machine, as wi-7c21e4 already accepts; a lost clone loses open items not yet decided

### B. Keep committed per-session event files (wi-a93f02 as decided)

Event files under .kb/_ledger/events in your repos; write an importer into redkiln-rs's store at integration.

- Holds if: redkiln-rs is happy to import and then ignore those files
- If wrong: your repos carry ledger history redkiln-rs never reads, and two ledgers drift apart while both run

### C. Commit open items as open_question atoms; no store

Every open item is an atom in .kb/_intake from the moment it is raised; git holds everything.

- Holds if: open items change status rarely
- If wrong: each triage, defer and default becomes a commit, and kb-ingest's handling of frequently changing open_question atoms is still unverified

| Criterion | A | B | C |
|---|---|---|---|
| Same shape as redkiln-rs | Yes | No | No |
| Ledger files in repo history | Decisions only | Every event | Every open item |
| Worktrees see each other's items | Natively | By scanning worktrees | After merge |
| Open items on another machine | Via the board, your repos | Via git | Via git |

## Decision outcome

Chosen: **A. Mirror redkiln-rs: git for decisions, a common-dir store for open items**, decided 2026-09-27T04:29:07Z.

The card's recommendation was A (recommended and pre-selected).
Trade-off: You are trading open items in git history for a ledger with the same shape redkiln-rs will absorb.
What would flip it: You want open items visible to other people or to CI in a shared repo. Then keep A and add a committed export on demand.
Why it might be wrong: A trusts the board for cross-machine continuity. If the board is off for a repo (client repos), a cloud session there starts with no open items, which is a real regression from B for client work.
Stability: 4 of 4 (Opus pick plus 3 Sonnet samples, each with the option order permuted and the recommendation removed). All samples judged options written by the same author, so this checks order and framing bias, not authorship bias.
