# Interactive rendering surfaces and token-efficient skill mechanics for a "decision ledger" skill (Claude Code + Claude desktop/Cowork/claude.ai), as of 2026-09-26

Scope note: the 2026-09-12 Weigh-In brief already verified the basics (Stop/SubagentStop `last_assistant_message`, prompt/agent hooks, PreToolUse `defer`, AskUserQuestion 1–4 × 2–4, removed from subagents, MCP elicitation modes, core skill frontmatter, plugin component list, unstable transcript JSONL). These notes cover specifics the brief did not, plus what changed between 2026-09-12 and 2026-09-26. Current Claude Code release at time of research: **v2.1.283 (September 25, 2026)** ([changelog](https://code.claude.com/docs/en/changelog)). Current Claude Desktop build: **v2.9939.2 (2026-09-24)** ([Desktop/Cowork changelog](https://claude.com/docs/cowork/changelog)). Docs were pulled as raw markdown from code.claude.com, claude.com/docs and platform.claude.com on 2026-09-26.

Biggest new finding relative to the brief: **Claude Code (CLI and Desktop) and Cowork can publish claude.ai Artifacts with runtime capabilities, including a server-side JSON document store (`db`) that the page writes and Claude reads back with the `ArtifactData` tool.** That gives one visual, interactive, persistent surface that works from both Claude Code and Cowork and hands answers back to the model, which the brief did not cover. It has plan, policy and org-setting limits (details under Q6).

## Q1. AskUserQuestion today: preview field, multiSelect, annotations/notes, header limits, rendering per client, timeout/settings

### Takeaway
AskUserQuestion is still 1–4 questions × 2–4 options with a ≤12-char header. It now carries an optional per-option `preview` string and returns per-question `annotations` (`preview`, `notes`), plus an optional free-form `response` and `afkTimeoutMs`. The terminal renders previews side by side and adds a notes field. The VS Code extension's question card does not show previews, and since v2.1.281 Claude no longer attaches them there. Answers can auto-continue on an opt-in idle timeout (`askUserQuestionTimeout`: 60s/5m/10m/never). It is a good surface for ≤4 quick decisions per call, but it cannot show a whole ledger.

### Cited Findings
- **Input schema (SDK typing, current):** `questions[]` of `{question, header, options: [{label, description, preview?}], multiSelect}`, plus `answers?`, `annotations?: Record<string, {preview?, notes?}>`, `metadata?: {source?}`. — [Agent SDK TypeScript reference › AskUserQuestion](https://code.claude.com/docs/en/agent-sdk/typescript)
- **Output schema:** `{questions, answers: Record<string,string>, response?, annotations?: Record<string,{preview?, notes?}>, afkTimeoutMs?}`. "`response` is set when the user typed a freeform reply instead of answering the structured questions; when present, Claude receives 'The user responded: …' instead of the per-question answer list." — [Agent SDK TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- **Limits:** `header` "Short label for the question (max 12 characters)"; `options` "Array of 2-4 choices"; "each `AskUserQuestion` call supports 1-4 questions with 2-4 options each"; "`AskUserQuestion` is not currently available in subagents spawned via the Agent tool". — [SDK: Handle approvals and user input](https://code.claude.com/docs/en/agent-sdk/user-input)
- **Previews in SDK hosts are opt-in:** `toolConfig.askUserQuestion.previewFormat`: unset means the field is absent and Claude generates no previews; `"markdown"` gives "ASCII art and fenced code blocks"; `"html"` gives "A styled `<div>` fragment (the SDK rejects `<script>`, `<style>`, and `<!DOCTYPE>` before your callback runs)". "The format applies to all questions in the session. Claude includes `preview` on options where a visual comparison helps (layout choices, color schemes) and omits it where one wouldn't." TypeScript only. — [SDK user-input › Option previews](https://code.claude.com/docs/en/agent-sdk/user-input)
- **Multi-select answers:** "For multi-select questions, pass an array of labels or join them with `", "`." Free text such as "Other" goes in `answers[question]`. — [SDK user-input](https://code.claude.com/docs/en/agent-sdk/user-input)
- **Terminal rendering of previews (from user bug reports, not official docs):** "When `AskUserQuestion` options include `preview` fields, the UI switches to a side-by-side layout (option list on left, preview pane on right)". In that layout the built-in "Other" free-text input was not rendered as of v2.1.217 (issue open). — [anthropics/claude-code#80070](https://github.com/anthropics/claude-code/issues/80070). The preview pane truncates long content with "N lines hidden" and could not be scrolled (March 2026, closed as duplicate). — [anthropics/claude-code#33062](https://github.com/anthropics/claude-code/issues/33062)
- **Terminal preview renders markdown and has a notes input:** "Fixed a performance regression in the `AskUserQuestion` preview dialog that re-ran markdown rendering on every keystroke in the notes input" (v2.1.70, Mar 6 2026); "Fixed AskUserQuestion preview content being cut off at the dialog edge instead of word-wrapping" (v2.1.181, Jun 17 2026); "Fixed AskUserQuestion preview notes being attached to a previously chosen option instead of the highlighted one" and "Fixed AskUserQuestion preview mode dropping the highlighted option when submitting a note with Enter" (v2.1.274, Sep 17 2026). — [changelog](https://code.claude.com/docs/en/changelog)
- **Notes and free text:** "Answer by picking an option, or type your own text through the `Other` row or the notes field. When you answer by typing your own text, Claude Code relays the answer with neutral wording so Claude follows what you wrote, including a request to wait or explain first." — [Tools reference › AskUserQuestion](https://code.claude.com/docs/en/tools-reference#askuserquestion-tool-behavior)
- **Timeout:** questions wait indefinitely by default. `askUserQuestionTimeout` accepts `"60s"`, `"5m"`, `"10m"` or `"never"` (default `"never"`), with user or managed scope, and requires v2.1.200+. On expiry "it submits any options you'd already selected and tells Claude you may be away from your keyboard", with a 20-second visible countdown. "Permission prompts, including plan approval, never auto-resolve on idle." — [Tools reference](https://code.claude.com/docs/en/tools-reference#question-auto-continue-timeout); [settings reference › askUserQuestionTimeout](https://code.claude.com/docs/en/settings-reference)
- **VS Code extension:** "[VSCode] Fixed Claude attaching option previews to multiple-choice questions in the chat panel, where the question card never shows them" (v2.1.281, Sep 23 2026). The extension supports multiline "Other" input with Shift+Enter (v2.1.30). "Claude's latest to-do list stays visible, and so does the text a pending question from Claude is asking about" (v2.1.225+). — [changelog](https://code.claude.com/docs/en/changelog); [VS Code docs](https://code.claude.com/docs/en/vs-code)
- **JetBrains:** "The plugin runs the `claude` command in your IDE's integrated terminal and connects to it", so questions render as in the terminal CLI. — [JetBrains docs](https://code.claude.com/docs/en/jetbrains)
- **Desktop Code tab:** "Added an inline card for multiple-choice questions from Claude, so you can pick an option and step through each question before your choices are sent as a single reply" (Desktop v1.15200.0, 2026-06-23, Code section). — [Desktop/Cowork changelog](https://claude.com/docs/cowork/changelog)
- **Remote Control / mobile / claude.ai:** "Claude Code keeps permission prompts and `AskUserQuestion` questions open until you answer them" when forwarded to a remote session. Push notifications are available for "permission prompts and questions". — [Remote Control](https://code.claude.com/docs/en/remote-control)
- **Cloud sessions (Claude Code on the web):** "If Claude asks a question and the session sits idle, you can still answer when you come back, up to environment expiry." — [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web)
- **Behavioural tuning:** "Claude now reserves the multiple-choice question prompt for decisions it genuinely cannot make itself" (v2.1.154). Also: "Fixed interactive tools (e.g., `AskUserQuestion`) being silently auto-allowed when listed in a skill's allowed-tools, bypassing the permission prompt and running with empty answers" (v2.1.69). — [changelog](https://code.claude.com/docs/en/changelog)
- **Headless answer injection:** "PreToolUse hooks can now satisfy `AskUserQuestion` by returning `updatedInput` alongside `permissionDecision: "allow"`, enabling headless integrations that collect answers via their own UI" (v2.1.85). — [changelog](https://code.claude.com/docs/en/changelog)
- **Channels conflict:** "Disabled `AskUserQuestion` and plan-mode tools when `--channels` is active" (v2.1.83). Plan-mode tools were restored in interactive `--channels` sessions in v2.1.126. No later entry re-enables AskUserQuestion. — [changelog](https://code.claude.com/docs/en/changelog)
- **Skill-level suppression:** skill frontmatter `disallowed-tools` can remove `AskUserQuestion` while the skill is active ("such as `AskUserQuestion` for a background loop"). — [Skills › frontmatter](https://code.claude.com/docs/en/skills#frontmatter-reference)

### Inferences
- For a ledger, AskUserQuestion suits the resolve step for 1–4 items per call. Each option's `preview` can hold a compact markdown evidence box or trade-off table in the terminal. That content is lost in VS Code, so the skill should keep option `description` self-sufficient.
- `annotations[q].notes` is the only structured side channel for a rationale such as "why I chose this", so the ledger writer should capture it along with `answers`.
- Because the "Other" input can disappear in preview layout (#80070, open), a ledger skill that relies on free-text overrides should avoid previews on questions where a custom answer is likely.
- The timeout default "never" suits end-of-chat ledger reviews. Setting `askUserQuestionTimeout` would silently auto-submit partial selections, which conflicts with ledger integrity. The skill should treat an `afkTimeoutMs` output as "deferred", not "decided".

### Gaps
- No official code.claude.com page documents how the terminal CLI renders `preview`: side-by-side layout, width split, monospace, and whether previews apply to multiSelect questions. Only user bug reports describe it.
- Whether the Desktop Code tab's question card or Cowork's question card renders `preview` is undocumented.
- How the CLI chooses the preview format (markdown vs HTML) for its own tool, since the SDK `previewFormat` is for SDK hosts, is not documented.
- claude.ai web chat has no AskUserQuestion documented in the sources reviewed.

## Q2. Skills as of September 2026: frontmatter, substitutions, `!` injection, progressive disclosure, authoring guidance

### Takeaway
Skill frontmatter is richer than the brief listed. It now includes `when_to_use`, `model`, `effort`, `background` (for forks), `disallowed-tools`, `shell`, `metadata`, `license` and `compatibility`, plus string substitutions for session ID, effort, skill dir, project dir and plugin root/data. The description listing is always in context: each entry is capped at 1,536 chars and the whole listing at 1% of the context window. The SKILL.md body enters once per invocation as a user message (cache-safe), and compaction re-attaches only the first 5,000 tokens per skill within a shared 25,000-token budget. `!` commands run pre-send and cost nothing in model turns, but they are disabled in Cowork and for synced skills.

### Cited Findings
- **Full frontmatter table (current):** `name`, `description` (recommended), `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort` (`low|medium|high|xhigh|max`), `context` (`fork`), `agent`, `background` (fork only; default `true`; v2.1.218+), `hooks`, `paths`, `shell` (`bash|powershell`), `metadata`, `license`, `compatibility` (≤500 chars). "Claude Code ignores a field it doesn't recognize without reporting an error." Booleans accept yes/no/on/off/1/0 as of v2.1.218. — [Skills › Frontmatter reference](https://code.claude.com/docs/en/skills#frontmatter-reference)
- **Description cap:** "the combined `description` and `when_to_use` text is truncated at 1,536 characters in the skill listing". `skillListingMaxDescChars` defaults to 1536. — [Skills](https://code.claude.com/docs/en/skills#frontmatter-reference); [settings reference](https://code.claude.com/docs/en/settings-reference)
- **Listing budget:** "The budget scales at 1% of the model's context window. When the listing overflows, Claude Code drops descriptions starting with the skills you invoke least." It can be raised with `skillListingBudgetFraction` (default `0.01`) or `SLASH_COMMAND_TOOL_CHAR_BUDGET`. `skillOverrides` values: `"on"`, `"name-only"`, `"user-invocable-only"`, `"off"`. — [Skills › Skill descriptions are cut short](https://code.claude.com/docs/en/skills#skill-descriptions-are-cut-short); [Override skill visibility](https://code.claude.com/docs/en/skills#override-skill-visibility-from-settings)
- **Invocation/context table:** default means the description is always in context and the full skill loads when invoked. `disable-model-invocation: true` means "Description not in context, full skill loads when you invoke". `user-invocable: false` means the description is always in context and only Claude can invoke. — [Skills › Control who invokes a skill](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill); the [context-window explorer](https://code.claude.com/docs/en/context-window) says such skills "cost zero context until this moment".
- **Lifecycle:** "the rendered `SKILL.md` content enters the conversation as a single message and stays there across later turns… Claude Code does not re-read the skill file on later turns." Re-invoking with identical rendered content adds only "a short note that the skill is already loaded". After compaction: "re-attaches the most recent invocation of each skill after the summary, keeping the first 5,000 tokens of each. Re-attached skills share a combined budget of 25,000 tokens." — [Skills › Skill content lifecycle](https://code.claude.com/docs/en/skills#skill-content-lifecycle)
- **Substitutions:** `$ARGUMENTS`, `$ARGUMENTS[N]`, `$N`, `$name` (from `arguments`), `${CLAUDE_SESSION_ID}`, `${CLAUDE_EFFORT}`, `${CLAUDE_SKILL_DIR}` (for plugin skills this is "the skill's subdirectory within the plugin, not the plugin root"), `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_PLUGIN_DATA}` (plugin skills only; the data dir "survives plugin updates"). — [Skills › Available string substitutions](https://code.claude.com/docs/en/skills#available-string-substitutions)
- **`!` dynamic context injection:** "runs shell commands before the skill content is sent to Claude. The command output replaces the placeholder." It is also available as a ```` ```! ```` fenced block. Substitution runs once and is not re-scanned. The inline form works only at line start or after whitespace. Commands run under the Bash tool's 2-minute default timeout. Output past the inline ceiling arrives as a file path plus preview. "A failed command aborts the entire skill invocation." Injected commands "never prompt for permission"; outside auto mode anything short of allow aborts, so pre-approve with `allowed-tools`. `disableSkillShellExecution: true` replaces commands with `[shell command execution disabled by policy]`. — [Skills › Inject dynamic context](https://code.claude.com/docs/en/skills#inject-dynamic-context)
- **Auto mode change:** "a skill's or slash command's inline `!` shell commands follow default-mode permission rules instead of the classifier" (v2.1.271). — [changelog](https://code.claude.com/docs/en/changelog)
- **Synced/Cowork restrictions:** "In a Cowork session on your desktop, the body keeps the behavior a local skill has, except that Claude Code replaces every `!` command line with the `disableSkillShellExecution` placeholder, as it does for every skill you supply there." In other local sessions, synced skills don't run `!` commands, don't attach `@` files, and don't substitute `${CLAUDE_PROJECT_DIR}` / `${CLAUDE_SESSION_ID}`. In cloud sessions the body keeps local behaviour. — [Skills › How Claude Code handles the body of a synced skill](https://code.claude.com/docs/en/skills#how-claude-code-handles-the-body-of-a-synced-skill)
- **`context: fork`:** "Claude Code starts a new subagent of the type set in the `agent` field and gives it the skill content as its prompt. The subagent doesn't see your conversation history." Despite the name it is not a conversation fork. It runs in the background by default; `background: false` waits. A backgrounded fork gets "the narrower tool set that applies to background subagents". "Built-in Explore and Plan agents skip CLAUDE.md and git status." — [Skills › Run skills in a subagent](https://code.claude.com/docs/en/skills#run-skills-in-a-subagent)
- **Skill hooks:** registered on invoke and "keeps running them for the rest of the session". `once: true` removes a hook after its first successful run and is "Only honored for hooks declared in skill frontmatter". — [Hooks › Hooks in skills and agents](https://code.claude.com/docs/en/hooks#hooks-in-skills-and-agents); [Hooks › Common fields](https://code.claude.com/docs/en/hooks#common-fields)
- **`allowed-tools` scope:** the grant covers only the invoking turn: "The grant clears when you send your next message." Workspace trust doesn't gate it. — [Skills › Pre-approve tools](https://code.claude.com/docs/en/skills#pre-approve-tools-for-a-skill)
- **Cost tooling:** `/skill-doctor` (v2.1.252+) reports each skill's context cost and usage. `/doctor` estimates listing cost. The VS Code Slash commands dialog now shows "each skill's source, token estimate and on/off state" (v2.1.280). `claude plugin details` prints "Always-on" (listing) vs "On-invoke" cost per component. — [Skills › Find unused skills](https://code.claude.com/docs/en/skills#find-unused-skills); [changelog](https://code.claude.com/docs/en/changelog); [Measure plugin cost](https://code.claude.com/docs/en/plugins/measure)
- **Anthropic authoring guidance (platform docs):** Level 1 metadata "~100 tokens per Skill" is always loaded. Level 2 SKILL.md body is "Under 5k tokens" when triggered. Level 3+ resources cost "None until accessed". "Scripts run through bash, and only their output enters context." `name` max 64 chars; `description` max 1024 chars (API/claude.ai spec; Claude Code's listing cap is 1,536 combined). "Keep SKILL.md body under 500 lines". "Keep references one level deep from SKILL.md". For reference files over 100 lines "include a table of contents at the top". Utility scripts are "More reliable than generated code / Save tokens / Save time". — [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview); [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); Claude Code repeats "Keep `SKILL.md` under 500 lines" ([Skills › Add supporting files](https://code.claude.com/docs/en/skills#add-supporting-files)).
- **Skills across surfaces:** skills load in claude.ai chat, Cowork and Claude Code. Commands load "as a skill" in chat. Agents and hooks are "Ignored" in chat and load in Cowork and Claude Code. `bin/` executables "Can't be installed" in chat or Cowork. — [Plugin feature support across platforms](https://claude.com/docs/plugins/platform-support)
- **Syncing:** Claude Code now downloads claude.ai-enabled skills into `~/.claude/skills/synced/` in terminal sessions signed in with claude.ai. The docs say this requires v2.1.273+, while the changelog lists it under v2.1.275 (Sep 17). Opt out with `syncClaudeAiSkills: false` / `syncClaudeAiPlugins: false`. — [Skills › Where synced skills load](https://code.claude.com/docs/en/skills#where-synced-skills-load); [changelog v2.1.275](https://code.claude.com/docs/en/changelog)

### Inferences
- Token-frugal shape: a short `description` (the only always-on cost), a SKILL.md under ~150 lines, and all deterministic ledger I/O (append, list, render, diff) in `scripts/`, invoked either by `!` injection (zero model turns) or by Bash.
- Because `!` injection is replaced in Cowork and in synced-skill contexts, the skill needs a fallback path in which Claude runs the same script via Bash, or a pure-prompt path. `!` injection is a Claude Code-local optimisation, not portable.
- Set `disable-model-invocation: true` on the review/resolve entry point so the ledger costs zero listing tokens until `/ledger` is typed. Keep a separate, tiny `user-invocable: false` capture skill only if auto-capture by Claude is wanted.
- `${CLAUDE_SESSION_ID}` provides the per-session ledger key, and `${CLAUDE_PROJECT_DIR}` the per-repo ledger location. Neither is substituted for synced skills in local sessions, so a ledger distributed via claude.ai sync breaks path assumptions. Ship it as a plugin or repo skill instead.
- Setting `model:` in a non-fork skill causes a full cache miss that turn (see Q7). Put the cheap model on a `context: fork` skill or a subagent instead.

### Gaps
- The exact number of characters or tokens the "1% of context window" budget equals is not stated. On a 1M-context model it would be large, but whether the budget is measured in tokens or characters is ambiguous: `SLASH_COMMAND_TOOL_CHAR_BUDGET` is characters, while the setting text says "share of the context window".
- The `arguments` field and `$name` are documented, but no typed argument schema exists.

## Q3. MCP Apps (SEP-1865, `ui://`): which Anthropic clients render them, how UI input flows back, limits

### Takeaway
MCP Apps went Stable on 2026-01-26. They render in claude.ai web, Claude Desktop chat, Cowork, iOS/Android, and (per the Desktop changelog) the Desktop Code tab. The Claude Code terminal CLI does not render them: it treats `ui://` resources as host-only and hides them. The VS Code extension has no documented support. A UI flows input back three ways: `tools/call` to its own server, `ui/message` (a user-role message that triggers a turn) and `ui/update-model-context` (context delivered on the next turn). Limits: sandboxed iframe with a restrictive default CSP, ~150k-char tool-result ceiling on claude.ai/Desktop, and multiple live widget instances.

### Cited Findings
- **Status:** "SEP-1865: MCP Apps: Interactive User Interfaces for MCP … Status: Stable (2026-01-26)". — [ext-apps spec 2026-01-26](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx); [SEP-1865](https://modelcontextprotocol.io/seps/1865-mcp-apps-interactive-user-interfaces-for-mcp)
- **Anthropic surfaces:** "Available in Claude on mobile, web and desktop for Free, Pro, Max, Team, Enterprise plans. Also now available on Claude Cowork." (Jan 26, 2026) — [Claude blog: Interactive connectors and MCP Apps](https://claude.com/blog/interactive-tools-in-claude). "Interactive connectors are available for all users on Claude, Cowork, Claude Desktop, and Claude for iOS/Android" (updated Aug 11, 2026). — [Help Center: Use interactive connectors](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude)
- **Community support matrix:** it lists Claude (web) and Claude Desktop with MCP Apps checks. Claude Code is not listed. VS Code appears only as "VS Code GitHub Copilot". — [MCP Extension Support Matrix](https://modelcontextprotocol.io/extensions/client-matrix) (community-maintained)
- **Claude Code terminal does not render them:** "MCP Apps UI resources are entries with a `ui://` URI or the `text/html;profile=mcp-app` media type: pages for a host application to render rather than content for Claude to read. They don't appear in the `@` suggestions or in the resource list tool's results… Reading a UI resource by its URI still works." Changelog v2.1.281 (Sep 23 2026): "Changed MCP resource lists … to skip MCP Apps UI resources". — [Claude Code MCP docs](https://code.claude.com/docs/en/mcp); [changelog](https://code.claude.com/docs/en/changelog)
- **Desktop Code tab renders them:** the Desktop v1.37937.0 (2026-08-25) 3P section says "Added Code tab features already available in the standard app: … interactive MCP app widgets in the conversation". — [Desktop/Cowork changelog](https://claude.com/docs/cowork/changelog)
- **Local MCP servers work on Desktop:** the official quickstart has you add example MCP App servers (run locally via `npx`) to `claude_desktop_config.json`. "Claude asks for permission to display the app. Click Allow, or Always allow… and the MCP App renders inline in the conversation." — [Get started with MCP Apps](https://claude.com/docs/connectors/building/mcp-apps/getting-started)
- **UI → model channels (spec):** Views may use `tools/call` and `resources/read`. `ui/message` sends `{role:"user", content:{type:"text"}}`: "Host SHOULD add the message to the conversation context… MAY request user consent". `ui/update-model-context` sends `{content?, structuredContent?}`: "This context will be used in future turns. Each request overwrites the previous context sent by the View… MAY defer sending the context to the model until the next user message… SHOULD only send the last update". Tools can be `visibility: ["app"]` (hidden from the model, callable from the UI). — [ext-apps spec 2026-01-26](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx)
- **Claude implements sendMessage / updateModelContext:** "Each time Claude calls a tool that renders an MCP App, Claude mounts a separate iframe in the conversation. No host API unmounts earlier instances… Each copy independently pushes model-context updates… and messages to Claude." Anthropic's guide shows a BroadcastChannel "election" so stale instances disable themselves. — [Supersede older widget instances](https://claude.com/docs/connectors/building/mcp-apps/instance-supersession)
- **Anthropic's interaction guidance:** handle direct manipulation, selections and "Confirming or executing a prepared action" in-app. Push "Text entry and freeform input… Follow-up questions or requests for clarification… Anything that benefits from Claude's interpretation" to the chat input. — [MCP Apps design guidelines](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines)
- **Security:** mandatory iframe sandboxing. If `ui.csp` is omitted, "Host MUST use: `default-src 'none'; script-src 'self' 'unsafe-inline'; … connect-src 'none'`". "Host MAY further restrict but MUST NOT allow undeclared domains." Web hosts must use a sandbox proxy on a different origin. — [ext-apps spec](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx). Claude serves apps from `{hash}.claudemcpcontent.com`, and `ui.domain` must be "the first 32 hex characters of the SHA-256 of your server URL, followed by `.claudemcpcontent.com`". On mobile, apps run in a native WebView with no camera, mic or location access. — [MCP Apps getting started](https://claude.com/docs/connectors/building/mcp-apps/getting-started); [design guidelines](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines); [troubleshooting](https://claude.com/docs/connectors/building/mcp-apps/troubleshooting)
- **Size limits:** "When a tool result exceeds approximately 150,000 characters and Claude's code execution sandbox is active, Claude writes the result to the sandbox filesystem… Your app receives a pointer… so it never hydrates." That threshold applies to claude.ai/Desktop; "Claude Code uses a separate 25,000-token default limit, configurable through `MAX_MCP_OUTPUT_TOKENS`". claude.ai/Desktop tool-call timeout is 240 s. — [MCP Apps troubleshooting](https://claude.com/docs/connectors/building/mcp-apps/troubleshooting); [Building custom connectors](https://claude.com/docs/connectors/building)
- **Display modes:** `inline | fullscreen | pip` via `ui/request-display-mode`. In fullscreen "The conversation composer remains available". — [spec](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx); [design guidelines](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines)

### Inferences
- An MCP App is the richest in-conversation ledger UI for Desktop chat, Cowork, claude.ai and the Desktop Code tab. It gives Ryan no terminal coverage, so on its own it misses the primary client (Claude Code terminal).

Tools marked `visibility:["app"]` (for example `ledger.save`) let the widget persist answers to the server without adding tool definitions to the model's context.
- On claude.ai web and Cowork, the MCP server must be a remote (HTTP) connector. On Desktop, a local stdio server works. For Ryan's `.NET/Azure` preference, a remote server on Azure (Functions/Container Apps) serving both the ledger store and the `ui://` resource would be the single backend for all non-terminal clients.
- Multiple widget instances will each push context. Anthropic's supersession pattern is required for a single-state ledger widget.

### Gaps
- No code.claude.com Desktop page confirms MCP Apps in the Code tab. The only evidence is the 3P changelog line ("already available in the standard app").
- There is no statement on whether the VS Code or JetBrains Claude Code extensions render MCP Apps. The evidence (CLI engine hides UI resources; not in the matrix) suggests not.
- The maximum UI HTML resource size in Claude, and any Claude-specific consent behaviour for `ui/message`, are not documented.
- Whether Cowork's cloud-run sessions can render MCP Apps from local (`host:`) MCP servers is unclear. Cowork docs say local connectors work only through the desktop app.

## Q5. The "local HTML page + tiny server or file write-back" pattern from inside Claude Code (Plannotator et al.)

### Takeaway
Plannotator shows two launch/return mechanics:
- **Plan review:** a blocking `PermissionRequest` command hook on `ExitPlanMode` (timeout 345,600 s) starts a local server, opens the browser, and returns the decision on hook stdout.
- **Ad-hoc review:** a `disable-model-invocation` skill tells Claude to run a blocking Bash command (`plannotator last|annotate|review`) whose stdout (JSON decision plus feedback) becomes the tool result.

Remote/SSH works via a fixed port and port forwarding. Claude Code cloud sessions have no documented way to reach a local browser. Claude Code also offers non-blocking return paths: the Monitor tool (watch a file or WebSocket), background-command completion notifications, and Channels (research preview; a localhost "fakechat" UI pushes messages into the session).

### Cited Findings
- **Plannotator plan flow:** "Agent calls ExitPlanMode → PermissionRequest hook fires → Local server reads plan from hook input → Browser opens with review UI → You annotate and approve/deny → Approve: agent proceeds → Deny: structured feedback sent to agent". Manual config: `"PermissionRequest": [{"matcher": "ExitPlanMode", "hooks": [{"type": "command", "command": "plannotator", "timeout": 345600}]}]`. — [Plannotator README](https://github.com/backnotprop/plannotator)
- **Plannotator skill flow:** `plannotator-last` SKILL.md (`disable-model-invocation: true`) says: "Run: `plannotator last` … 1. Launch the command with Bash. 2. Wait for the annotation session to finish. 3. If feedback is returned, incorporate it… 5. An approval may still carry notes — a `"decision": "approved"` result with a `"feedback"` field." `plannotator annotate <path> --gate --json` adds an Approve button. — [plannotator-last](https://raw.githubusercontent.com/backnotprop/plannotator/main/apps/skills/core/plannotator-last/SKILL.md); [plannotator-annotate](https://raw.githubusercontent.com/backnotprop/plannotator/main/apps/skills/core/plannotator-annotate/SKILL.md)
- **Plannotator remote:** "auto-detects SSH sessions and switches to a fixed port. `PLANNOTATOR_REMOTE=1`, `PLANNOTATOR_PORT=9999` # forward this port… VS Code devcontainers forward the port automatically". Default port: random locally, `19432` in remote mode. Settings live in cookies "because each hook invocation runs on a random port." — [Plannotator README](https://github.com/backnotprop/plannotator); [apps/hook/README.md](https://raw.githubusercontent.com/backnotprop/plannotator/main/apps/hook/README.md)
- **Bash tool limits (governs the blocking-command pattern):** default timeout two minutes (`BASH_DEFAULT_TIMEOUT_MS`), ceiling ten minutes (`BASH_MAX_TIMEOUT_MS`). "When a command reaches its timeout without finishing, Claude Code moves it to the background instead of stopping it", reporting "Command did not complete within its 120s timeout and was moved to the background" plus the task ID and output file. Claude is notified when a background command ends. — [Tools reference › Bash](https://code.claude.com/docs/en/tools-reference#timeout-and-output-limits)
- **Monitor tool (non-blocking watcher):** it can "Watch a directory for file changes", tail output, or "Connect to a WebSocket feed and report each message as it arrives". "Every watch Claude starts has a deadline: 5 minutes by default, at most 30 minutes, and at most 10 minutes in a non-interactive run". — [Tools reference › Monitor tool](https://code.claude.com/docs/en/tools-reference#monitor-tool)
- **Hook return paths:** a hook's `additionalContext`, `systemMessage` and stdout are capped at 10,000 chars. Longer output is written to a file and Claude gets "the file path with a preview of up to the first 2,000 characters". Stop/SubagentStop `additionalContext` arrives "at the end of the turn. The conversation continues so Claude can act on the feedback." Async command hooks deliver output "on the next conversation turn". — [Hooks › Add context for Claude](https://code.claude.com/docs/en/hooks#add-context-for-claude); [Hooks › Run hooks in the background](https://code.claude.com/docs/en/hooks)
- **Channels:** "A channel is an MCP server that pushes events into your running Claude Code session… Channels can be two-way". It is a research preview, requires claude.ai or Console auth, and Team/Enterprise must enable it. "Fakechat is an officially supported demo channel that runs a chat UI on localhost… you can type in the browser and the message arrives in your Claude Code session." Requires `claude --channels plugin:…` and Bun. — [Channels](https://code.claude.com/docs/en/channels). AskUserQuestion is disabled while `--channels` is active (v2.1.83). — [changelog](https://code.claude.com/docs/en/changelog)
- **Artifact "copy as prompt" pattern (official):** "An artifact can act as a lightweight editor for a decision you then send back to Claude. Ask for an export control that produces text you can paste into the terminal". — [Claude Code Artifacts › Bring the result back to your session](https://code.claude.com/docs/en/artifacts#bring-the-result-back-to-your-session)
- **Desktop Code tab browser pane:** "HTML, PDF, image, and video paths open in the Browser pane". Claude can start dev servers and read/interact with pages via preview tools (`.claude/launch.json`), and localhost addresses open directly. — [Desktop › Preview your app](https://code.claude.com/docs/en/desktop)
- **Cloud sessions:** they run in Anthropic-hosted VMs with network access "limited by default". You interact via claude.ai or mobile, and "Commands that only run in the terminal interface, such as `/plugin` or `/resume`, aren't available." — [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web)
- **Remote Control:** when a prompt arrives via Remote Control from claude.ai, Desktop or mobile, a newly published artifact does not open a tab on the session machine. — [Artifacts › Create an artifact](https://code.claude.com/docs/en/artifacts#create-an-artifact)

### Inferences
- There are four viable return mechanisms for a local ledger page in the terminal, ordered cheapest first:
  1. **Blocking Bash command.** A `ledger review` binary serves the page and exits with a compact JSON result. This costs one tool call and one small result. It is capped at 10 minutes blocking and then backgrounds, with a later notification.
  2. **Page writes to `.ledger/answers.json`, Claude reads it on next invocation.** This is fully async, but Claude reads only when prompted.
  3. **Monitor tool on that file.** Near-live, but deadlines are 5–30 minutes and each event costs a turn.
  4. **Channels.** True push, but a research preview, disables AskUserQuestion, and needs `--channels` at launch. Unsuitable as the default.
- A `PermissionRequest`/`PreToolUse` hook on a sentinel tool (Plannotator-style) is the only way to hold a turn open indefinitely without the Bash 10-minute ceiling (Plannotator uses a 4-day hook timeout).
- In SSH or devcontainer sessions the local-page pattern works with a fixed port and forwarding. In Claude Code cloud sessions it does not, and the portable replacement is a published Artifact (Q6) or AskUserQuestion answered through claude.ai.

### Gaps
- Plannotator's exact stdout JSON schema for the `PermissionRequest` decision, and how it handles the hook `timeout` vs the browser session, were not verified in source code.
- No official doc describes whether the Desktop Code tab's Browser pane can POST back to a session-local server launched by a skill, beyond generic localhost preview.
- There is no confirmation of how Claude Code's Bash tool behaves when a command opens a browser under Remote Control (the `open`/`xdg-open` target is the session host).

## Q7. Token cost mechanics: caching with skills and hooks, fork/subagent cost, cheaper models for sub-steps, hook types that cost tokens

### Takeaway
Skills and plugin components never invalidate the prompt cache: they append. Command, http and mcp_tool hooks cost zero model tokens except for what they inject, and injected text over 10k chars is spilled to a file. Prompt hooks call a model (Haiku by default). Agent hooks spawn a subagent of up to 50 turns.

Subagents and `context: fork` skills start a fresh, uncached prefix with a 5-minute TTL and re-load CLAUDE.md and git status unless the agent is Explore/Plan or sets `omitClaudeMd`. Conversation forks (`/subtask`, fork mode) reuse the parent cache. Setting `model:` on a non-fork skill forces a full cache miss for that turn. Setting it on a `context: fork` skill or subagent is the cheap way to run steps on Haiku or Sonnet.

### Cited Findings
- **Skills and cache:** "Skills and commands inject their instructions as user messages at the point of invocation. Nothing earlier in the conversation changes." "Claude Code never invalidates the cache for a plugin's skills, commands, agents, hooks, monitors, or themes. It appends their content after the existing conversation". — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **`model:` in a skill is a cache break:** "When a skill or command's frontmatter names a `model` other than the session's current model, that turn is also a model switch: the next request reads the entire conversation history with no cache hits… A `context: fork` skill sets the forked subagent's model instead." — [Prompt caching › Switching models](https://code.claude.com/docs/en/prompt-caching#switching-models). Effort changes and MCP tool-set changes (without tool search) also invalidate the cache. — same page
- **Subagent cache:** "Its first request doesn't read the parent's cache… Subagents fall outside the main-conversation TTL bucket, so they get five minutes even on a subscription". "A fork, by contrast, inherits the parent's system prompt, tools, and conversation history exactly, so its first request reads the parent's cache." — [Prompt caching › Subagents and the cache](https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache)
- **TTL defaults:** main conversation gets 1 hour on a subscription within plan usage and 5 minutes on usage credits, API key or cloud. "Everything else" (subagents, workflows, forks, compaction) gets 5 minutes. Override with `promptCacheTtl` / `subagentPromptCacheTtl` (v2.1.242+) or per-subagent `experimental.cacheTtl` (v2.1.248+). — [Prompt caching › Cache lifetime](https://code.claude.com/docs/en/prompt-caching#cache-lifetime)
- **What a non-fork subagent loads:** its own system prompt, the task message, the full CLAUDE.md hierarchy ("The built-in Explore and Plan agents skip this"; `omitClaudeMd` to opt out), a git status snapshot (Explore/Plan skip), preloaded skills (full content), and a sibling roster. "It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read." — [Sub-agents › What loads at startup](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup)
- **Fork vs non-fork:** fork gets full history, the same model and a shared prompt cache. Non-fork gets fresh context, the model from its `model` field, and a separate cache. "This makes forking cheaper than spawning a fresh subagent for tasks that need the same context." Fork mode is on by default interactively (v2.1.232+) and off in `-p` and the SDK. — [Sub-agents › Fork the current conversation](https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation)
- **Cheaper model for sub-steps:** "For simple subagent tasks, specify `model: haiku` in your subagent configuration." "The subagent's own requests still draw on your usage. To spend less on them, choose a smaller model for a subagent or run every subagent on one model." `CLAUDE_CODE_SUBAGENT_MODEL` does not by itself change Explore/Plan; its precedence changed in v2.1.251. — [Costs › Choose the right model](https://code.claude.com/docs/en/costs#choose-the-right-model); [Sub-agents › Choose a model](https://code.claude.com/docs/en/sub-agents#choose-a-model)
- **Hook types and cost:** `claude plugin details` labels a hook "(harness-only — no model context cost)". "Hooks and MCP servers get no cost estimate". — [Measure plugin cost](https://code.claude.com/docs/en/plugins/measure). Prompt hooks "Send the hook input and your prompt to a Claude model, Haiku by default" (optional `model`). Agent hooks spawn a subagent that runs "up to 50 turns" (default 60 s timeout, "experimental"). All five types (command/http/mcp_tool/prompt/agent) are supported on Stop, SubagentStop, PreToolUse, PostToolUse, PostToolBatch, UserPromptSubmit and several others. SessionStart and Setup support only command and mcp_tool. — [Hooks › Prompt-based hooks](https://code.claude.com/docs/en/hooks#prompt-based-hooks); [Agent-based hooks](https://code.claude.com/docs/en/hooks#agent-based-hooks)
- **Hook injection size:** "A hook's `additionalContext`, `systemMessage`, and `initialUserMessage` strings, and its plain stdout, are capped at 10,000 characters". Over that, the text goes to a file and Claude gets a path plus a 2,000-char preview (since v2.1.89). Injected text is saved to the transcript and replayed (not re-run) on resume. — [Hooks › Add context for Claude](https://code.claude.com/docs/en/hooks#add-context-for-claude)
- **Stop prompt-hook repeat cost fixed:** "Fixed Stop prompt hooks re-sending their whole prompt on every block in a conversation; repeat blocks now name the condition with a 500-character label" (v2.1.274, Sep 17). — [changelog](https://code.claude.com/docs/en/changelog)
- **Cache-miss regressions fixed since 09-12 (relevant to hooks/skills):** SessionStart hook output after `/clear` caused "a full prompt-cache miss" (fixed v2.1.277). Resumed fork subagents "broke prompt caching" (fixed v2.1.280). "Fixed `DISABLE_PROMPT_CACHING_HAIKU` having no effect when Haiku is the session's main model" (v2.1.283). — [changelog](https://code.claude.com/docs/en/changelog)
- **Offload guidance:** "Custom hooks can preprocess data before Claude sees it… reducing context from tens of thousands of tokens to hundreds." "Move instructions from CLAUDE.md to skills". "Delegate verbose operations to subagents". — [Costs › Reduce token usage](https://code.claude.com/docs/en/costs#reduce-token-usage)
- **Observability:** `/usage` attributes usage "to skills, subagents, plugins, and individual MCP servers, each shown as a percentage". A `Prompt cache (main)` line counts misses (a miss is a request that re-processed >5% and ≥2,000 tokens of cacheable content). It covers the main conversation only, not subagents. — [Costs › Track your costs](https://code.claude.com/docs/en/costs)
- **Current prices (context for trade-offs):** Opus 5.5 (default Opus since v2.1.280, Sep 22) costs "$4/$20 per Mtok with $0.20/Mtok cache reads", with 1M context. Opus 5.5 always uses extended thinking ("You can't turn off thinking on Opus 5.5 or the Fable models"). — [changelog](https://code.claude.com/docs/en/changelog); [Costs](https://code.claude.com/docs/en/costs)
- **MCP overhead:** MCP tool definitions are "deferred by default" (tool search). CLI tools are "more context-efficient than MCP servers because they don't add any per-tool listing". — [Costs › Reduce MCP server overhead](https://code.claude.com/docs/en/costs)
- **Skill authoring economics:** "At startup, only the metadata (name and description) from all Skills is pre-loaded… 'Does this paragraph justify its token cost?'" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)

### Inferences
- **Cheapest ledger capture:** a `Stop` command hook (zero model tokens) that runs a deterministic extractor on `last_assistant_message` (regex or heading conventions) and appends to `.ledger/*.jsonl`. It should inject nothing, or a one-line `systemMessage` count. A `prompt` hook on every Stop costs a Haiku call per turn. Reserve it for turns where the command hook detects candidate markers, or run it as an async command hook calling the Haiku API offline.
- **Cheapest ledger review in-session:** a `disable-model-invocation: true` skill whose `!` injection prints only the pending items (capped, for example top 5 by impact) as compact text. One append-only user message, cache-safe, then AskUserQuestion. Avoid `model:` on this skill, because that forces a full uncached re-read of the conversation, which is expensive at the end of a long chat.
- **Grounding or triage that needs file reading:** use `context: fork` + `agent: Explore` + a Haiku/Sonnet `model` so it gets no CLAUDE.md, no git status and no history. The trade-off is an uncached fresh prefix with a 5-minute TTL. Alternatively use a conversation fork (`/subtask`) when the chat history itself is the input, since it reuses the parent cache but runs on the main model.
- A published Artifact's HTML is output-token-heavy only when (re)generated. Publish the ledger page once and move data via `db`, so per-run output tokens stay small.

### Gaps
- There are no official numbers for the token cost of a prompt-hook call or of the Haiku default model version used by prompt hooks.
- There is no official guidance on the per-turn token cost of the AskUserQuestion tool definition or result.
- Whether `context: fork` skills honour `subagentPromptCacheTtl` identically to Agent-tool subagents is implied (the "everything else" bucket) but not stated for skills specifically.

## Q8. Consolidated per-client surface map (synthesis of Q1–Q7)

### Takeaway
There is no single interactive surface that is visual, persistent and answer-returning across every client except published Artifacts with `db`, and those have plan and org-policy prerequisites. AskUserQuestion is the only native surface in every Claude Code client, but it is small and non-visual beyond terminal previews. MCP Apps cover Desktop, Cowork, web and mobile but not the terminal. Local pages cover the terminal, IDE and SSH but not cloud sessions or Cowork.

### Inferences
- **Layered design implied by the map:**
  1. A repo-local, append-only ledger file (`.ledger/`) as the source of truth, written by command hooks and scripts at zero model tokens.
  2. AskUserQuestion for quick in-chat resolution of ≤4 items in any Claude Code client, including Cowork.
  3. One per-repo published Artifact with `db` as the visual, persistent, cross-client board: open from any chat, answer on the page, and Claude pulls answers with one `ArtifactData` read at the next `/ledger` run.
  4. Optionally, a local `ledger review` page for air-gapped or ZDR orgs where artifacts are unavailable.
- MCP Apps are worth adding only if Cowork/Desktop-chat use of the ledger becomes primary, because they need a remote MCP server and give no terminal coverage.
